# 领域文档

本项目采用 **single-context** 布局。工程技能探索代码、撰写规格或提出设计变更时，遵循以下文档读取约定。

## 探索前读取

1. 阅读根目录 `AGENTS.md`，遵守项目的强制开发规范。
2. 若存在根目录 `GLOSSARY.md`，阅读与当前任务有关的术语定义。
3. 若存在 `docs/adr/`，阅读影响当前模块或设计的架构决策记录。
4. 涉及分层、缓存、响应或外部调用时，参考现有 `docs/architecture/` 中的相关说明；接口契约和实现事实以已确认需求、源码、测试及架构文档为准。

如果 `GLOSSARY.md` 或 `docs/adr/` 尚不存在，直接继续，不把缺失视为错误，也不提前创建占位文件。以后使用 `domain-modeling` 等领域技能时，只在术语或架构决策得到确认后创建对应文档。

## 文件布局

```text
ai-/
├── AGENTS.md
├── GLOSSARY.md          # 按需创建的领域词汇表
├── app/
└── docs/
    ├── agents/          # 工程技能的项目配置
    ├── architecture/    # 现有架构与实现说明
    └── adr/             # 按需创建的架构决策记录
```

当前不需要 `GLOSSARY-MAP.md` 或按子上下文拆分目录。以后仓库演变为多个业务上下文时，再明确调整此约定。

## 使用统一术语

任务标题、规格、重构建议、设计假设和测试名称中的领域概念，使用 `GLOSSARY.md` 已定义的词汇，不随意替换为词汇表明确排除的同义词。

需要的概念尚未定义时，先核实是否属于项目已有业务语言；确有定义缺口时记录为待澄清项，不编造已确认术语。

## 显式说明架构决策冲突

建议或实现与现有 ADR 冲突时，指出对应 ADR、冲突内容和重新讨论的原因，不静默覆盖既有决策。
