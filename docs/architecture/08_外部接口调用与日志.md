# 外部接口调用与异常日志

所有业务统一通过 `App\Services\ExternalHttpClient` 调外部接口。认证客户端只负责认证路径和参数，其他业务无需依赖 `HttpExternalAuthClient`。不直接使用 `Http::get()` / `Http::post()`，也不需要在每个接口重复写日志。

## 网关分流

| 业务 | 网关选择 | 环境变量 |
| --- | --- | --- |
| 登录认证、登录短信、身份确认、数证 | `ExternalGateway::IDENTITY` | `IDENTITY_GATEWAY_BASE_URL`，默认 `http://101.200.147.55:18080` |
| 其他业务 | `ExternalGateway::DEFAULT`（默认值） | `EXTERNAL_HTTP_BASE_URL`，未设置时回退 `MEMBER_AUTH_BASE_URL` 的原网关地址 |

新增接口传网关内的相对路径，包含上游模块前缀和 API 版本。不要在业务代码中硬编码主机/IP，也不要根据本地路由或 `service` 字符串猜测网关。`service` 仅供日志检索，网关由 `gateway` 参数确定。

保留旧 `MEMBER_AUTH_BASE_URL` 的原值，供其他业务继续使用原网关。登录客户端的 `services.member_auth.base_url` 配置键保留兼容，但其值现在来自 `IDENTITY_GATEWAY_BASE_URL`；登录 URL 的 `api-iam/api/v1` 前缀仍按原配置拼接。

原有传完整 URL 的调用仍请求原地址，`gateway` 不会重写完整 URL 的主机；需要按网关分流的新调用应使用相对路径。未配置网关或显式配置空值时记录配置错误，不跨网关重试。当前尚无数证业务客户端，接入时按下面的身份网关示例使用。

## 新接口怎么使用

在业务 Service 或对应的业务客户端中注入通用客户端：

```php
use App\Services\ExternalHttpClient;
use Illuminate\Http\Client\Response;

public function __construct(private ExternalHttpClient $http) {}

// 路径仅为示例，普通业务默认走原网关。
$response = $this->http->post(
    url: '/orders/query',
    data: ['orderId' => $orderId],
    isSuccessful: static fn (Response $response): bool => $response->json('code') === 'OK',
    options: ['headers' => ['Authorization' => 'Bearer '.$token]],
    service: 'orders',
);
```

数证显式选择身份网关；无需依赖认证客户端，也无需另写日志：

```php
use App\Enums\ExternalGateway;

$response = $this->http->post(
    url: $certificatePath, // 数证上游契约中的相对路径，包含模块/API 前缀
    data: $params,
    isSuccessful: $isCertificateSuccessful, // 按数证上游契约定义的成功判断
    options: ['headers' => ['Authorization' => 'Bearer '.$token]],
    service: 'digital_certificate',
    gateway: ExternalGateway::IDENTITY,
);
```

GET 使用 `$this->http->get(...)`，`data` 自动作为查询参数。PUT/PATCH/DELETE 等使用 `$this->http->request('PATCH', $url, $data, ...)`，默认以 JSON 传参。`options` 支持 `headers`、`timeout`、`connect_timeout`、`form_params`、`multipart` 等 Laravel/Guzzle 选项。默认不跟随重定向，3xx 也作为 HTTP 异常记录。

`isSuccessful` 必须按上游契约填写，例如 `code === 'OK'`、`code === 0` 或 `success === true`。同一业务的规则可在业务客户端的内部请求方法中定义一次。**不传该规则时只判断 HTTP 2xx，不能识别 HTTP 200 的业务失败。**

HTTP/业务失败仍返回上游 `Response`，业务层负责按接口契约抛业务异常或转换响应。连接、配置和判断规则自身的异常会记录一次后继续抛出；认证客户端会将它们转换为原来的 `ExternalAuthResult` 错误结果。

## 自动记录的内容

仅失败写入 `storage/logs/external-http-YYYY-MM-DD.log`，事件名固定为 `external_http_failure`。`failure_type` 区分 `configuration`、`connection`、`http`、`invalid_response`、`upstream_business` 和 `exception`。

每条日志包含 `service`、`gateway`、`request_id`、实际请求 URL/路径、HTTP 方法、耗时、HTTP 状态、上游 `code`、`msg/message`、`traceId/trace_id`（或 `X-Trace-Id` / `traceId` 响应头）、本地请求路径/路由/控制器，以及请求字段和响应结构摘要。异常记录类名、脱敏消息和文件行号。完整 URL 调用中的 `gateway` 表示调用方选择的网关；实际目标以日志 `request_url` 为准。

`request_id` 优先采用合法的 `X-Request-Id` 请求头，否则自动生成。同一个本地请求中所有外部调用复用该 ID；调用上游时也携带它，方便前端和上游关联查询。

密码、验证码、Token、ticket、Authorization、Cookie 等不写入日志。完整请求体、完整响应体也不记录；请求值只保留白名单字段和脱敏账号/手机号，URL 查询值默认隐藏。上游错误消息和异常消息会按已知凭证清洗。响应仅记录字段列表、Content-Type 和原文长度，不存原文。

## 配置与查询

```dotenv
# 旧变量保留原网关值；旧环境只配置它也能供普通业务继续使用
MEMBER_AUTH_BASE_URL=https://original-gateway.example.com
# 可选：显式设置原业务网关；不设置时兼容 MEMBER_AUTH_BASE_URL
# EXTERNAL_HTTP_BASE_URL=https://original-gateway.example.com
# 登录与数证共用
IDENTITY_GATEWAY_BASE_URL=http://101.200.147.55:18080

EXTERNAL_HTTP_CONNECT_TIMEOUT_SECONDS=3
EXTERNAL_HTTP_TIMEOUT_SECONDS=10
EXTERNAL_HTTP_LOG_LEVEL=warning
EXTERNAL_HTTP_LOG_DAYS=30
```

日志级别保留 `warning` 或更低，确保失败日志不会被过滤。原 `EXTERNAL_AUTH_LOG_LEVEL` / `EXTERNAL_AUTH_LOG_DAYS` 仍作为兼容回退；新变量优先。认证自身的 `MEMBER_AUTH_*TIMEOUT_SECONDS` 继续覆盖其请求超时。

改了配置且部署使用配置缓存时，需要重新生成配置缓存。新版认证和其他业务共用 `external-http` 文件，旧 `external-auth` 文件保留为历史记录。

先按 `service`、接口路径、时间筛选，再用 `request_id` 关联本地调用，用 `upstream_trace_id` 查询上游。例如：

```powershell
Get-ChildItem storage/logs/external-http-*.log | Select-String -SimpleMatch '你的请求ID'
```
